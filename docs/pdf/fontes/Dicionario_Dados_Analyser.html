Dicionário de Dados — Tabelas do Prisma Analyser

Quatro tabelas propostas para o banco prisma-dev

Documento complementar à Proposta de criação de tabelas · Setembro de 2026

Convenções

  • Nulo: se a coluna aceita ausência de valor. Não significa NOT NULL — o banco recusa a gravação sem valor. Sim significa que o campo pode ficar vazio, por um de três motivos: o dado ainda não existe (o resumo, antes de o modelo responder), não se aplica àquela linha (nr_partido num item de político) ou pode faltar na origem (id_midia, quando o artigo não tem veículo associado).
  • Chave: PK = chave primária, FK = chave estrangeira, UQ = restrição de unicidade, IX = indexado.
  • Hashes são SHA-256 em hexadecimal minúsculo, sempre 64 caracteres.
  • Timestamps usam TIMESTAMPTZ (com fuso), gravados em UTC.
  • Eixo e rótulo assumem exatamente três valores: positivo, negativo, neutro.
  • Colunas *_json usam JSONB.
Identificação do ator

O ator é sempre representado por entity_type mais um de dois campos: nr_titulo_eleitoral_candidato quando é político, nr_partido quando é partido. O outro fica nulo. É a mesma convenção já usada em tabela_classificacao, e as tabelas do Analyser trazem uma restrição CHECK que garante que exatamente um dos dois esteja preenchido.

1. analyser_inbox_evento

Uma linha por mensagem recebida do Classifier. Impede que a mesma mensagem seja processada duas vezes e permite reprocessar depois sem pedir nada ao Classifier.

article_idBIGINTnãoIXIdentificador do artigo no Scraper. Corresponde a tabela_classificacao.id_artigo_scrape.
pipeline_versionVARCHAR(50)nãoIXVersão do pipeline que classificou o artigo. Junto com article_id, localiza as linhas de classificação correspondentes.
payload_jsonJSONBnãoA mensagem inteira, como chegou. Guarda também schema_version, job_id e notificado_em, que não viram coluna porque raramente são filtrados. Permite reprocessar sem depender do Classifier.

2. analyser_item

Uma linha por artigo × ator, já com o resumo — dos trechos classificados para aquele ator, nunca do artigo inteiro. É a unidade de trabalho do Analyser: um artigo que cita cinco atores gera cinco linhas — uma por ator, nunca uma por classificação. Um mesmo ator pode ter sido classificado em vários parágrafos, e todas essas classificações entram na mesma linha (ver trechos_json abaixo); os parágrafos que falam de um ator não são os mesmos que falam de outro, e um resumo escrito a partir de um recorte não serve para o outro.

ColunaTipoNuloChaveDescrição
item_idTEXTnãoPKIdentificador composto por artigo e ator, no formato art_1__politico_122418060191. Não inclui a versão do pipeline: uma reclassificação do mesmo artigo atualiza a mesma linha.
evento_idBIGINTnãoFKMensagem que originou o item. Referencia analyser_inbox_evento.
article_idBIGINTnãoIXArtigo no Scraper. Permite voltar a tabela_classificacao.
entity_typeVARCHAR(20)nãoIXpolitico ou partido.
nr_titulo_eleitoral_candidatoVARCHAR(20)simIXTítulo eleitoral do político. Nulo quando o item é de partido.
nr_partidoINTsimIXNúmero do partido. Nulo quando o item é de político.
ator_nomeVARCHAR(255)nãoNome do ator no momento em que a linha foi gravada, lido de entidade_matching.nome_principal. É um retrato, não um espelho: se a carga do TSE for refeita e o nome mudar, esta coluna preserva o que foi usado na geração do texto. Para o nome corrente, a API consulta entidade_matching. Este é o nome que entrou no prompt do resumo.
id_midiaINTsimVeículo, copiado da classificação. Nulo quando o artigo não tem mídia associada — situação real e aceita.
link_noticiaTEXTsimURL da notícia.
data_publicacaoTIMESTAMPTZsimData de publicação informada pelo Classifier.
janela_mesCHAR(7)nãoIXMês de agrupamento no formato 2026-08. Derivado da data de publicação e usado para montar o panorama.
rotulo_definitivoVARCHAR(10)nãoUm único rótulo para este item — os trechos do artigo que citam este ator —, calculado a partir deles. Não é o sentimento do artigo inteiro, só da parte que fala dele. É definitivo: se o mesmo item reaparecer com rótulo diferente, o evento é rejeitado em vez de sobrescrito.
regra_agregacao_versaoVARCHAR(30)nãoIdentifica a regra que produziu o rótulo, por exemplo maioria-v1. Sem isto, trocar a regra no futuro tornaria os rótulos antigos incomparáveis com os novos.
trechos_jsonJSONBnãoAs classificações recebidas para este ator, uma entrada por trecho. Ver detalhamento abaixo.

temas_jsonJSONBsimLista de temas curtos extraídos junto com o resumo.
modeloVARCHAR(100)simModelo que produziu o resumo, por exemplo qwen3.5:9b.
hash_prompt_resumoCHAR(64)simSHA-256 do prompt usado. Permite reproduzir a execução sabendo exatamente qual texto de instrução a gerou.

statusVARCHAR(20)nãonovo, resumido ou erro.
criado_emTIMESTAMPTZnãoCriação da linha.
atualizado_emTIMESTAMPTZnãoÚltima alteração.

Conteúdo de trechos_json

Array de objetos, um por classificação recebida para aquele ator naquele artigo:

[{"paragraph_index": 0, "classificacao_sentimento": "negativo", "score_confianca": 1.0},
 {"paragraph_index": 2, "classificacao_sentimento": "negativo", "score_confianca": 1.0},
 {"paragraph_index": 5, "classificacao_sentimento": "neutro",   "score_confianca": 0.0}]
Por que este campo existe

É a conta que produziu o rotulo_definitivo: no exemplo acima, dois negativos contra um neutro resultam em negativo. Sem ele, a pergunta “por que este item é negativo?” não tem resposta.

Mais importante: paragraph_index não é coluna de tabela_classificacao. Ele só existe na mensagem do RabbitMQ e no payload do outbox do Classifier. Se o Analyser não o guardar aqui, o dado desaparece quando aquele outbox for expurgado — e com ele a única forma de saber a que parágrafo cada classificação se referia.

O texto do parágrafo não é copiado: ele já está em tabela_classificacao.paragrafo_analisado, e duplicá-lo dobraria o maior conteúdo textual do banco sem acrescentar informação.

3. analyser_panorama

Todas as versões dos panoramas mensais. Um panorama é o texto consolidado de um ator, num mês, num eixo — é o produto que a API entrega ao frontend.

execucao_idBIGINTsimFKRodada que gerou este panorama. Referencia analyser_execucao.
entity_typeVARCHAR(20)nãoUQpolitico ou partido.
nr_titulo_eleitoral_candidatoVARCHAR(20)simUQPolítico. Nulo quando o panorama é de partido.
nr_partidoINTsimUQPartido. Nulo quando o panorama é de político.
ator_nomeVARCHAR(255)nãoNome do ator no momento em que a linha foi gravada, lido de entidade_matching.nome_principal. É um retrato, não um espelho: se a carga do TSE for refeita e o nome mudar, esta coluna preserva o que foi usado na geração do texto. Para o nome corrente, a API consulta entidade_matching.
janela_mesCHAR(7)nãoUQMês do panorama, formato 2026-08.
eixoVARCHAR(10)nãoUQpositivo, negativo ou neutro.
versaoINTnãoUQComeça em 1 e cresce a cada recálculo. Versões anteriores nunca são apagadas nem sobrescritas; a API expõe apenas a maior.

4. analyser_execucao

Uma linha por rodada de processamento. É o único registro que atravessa vários itens e vários panoramas, e por isso não cabe nas outras tabelas.

numero_execucaoINTnãoNúmero sequencial legível da rodada.
statusVARCHAR(20)nãoem_andamento, concluida ou falhou.

quantidade_eventosINTnãoEventos processados na rodada.
quantidade_itensINTnãoItens criados ou atualizados.
quantidade_resumosINTnãoResumos efetivamente pedidos ao modelo. A diferença para quantidade_itens é o que foi reaproveitado do cache.

iniciado_emTIMESTAMPTZnãoInício da rodada.
finalizado_emTIMESTAMPTZsimFim da rodada.
auditoria_jsonJSONBsimRegistro completo da auditoria: ids de entrada, ids vindos do cache, tokens consumidos, hashes de prompt e erros.

5. DDL proposta

Sujeita a ajuste de tipos e de schema conforme a orientação do responsável pelo banco.

CREATE TABLE analyser_inbox_evento (
    evento_id        BIGSERIAL   PRIMARY KEY,
    payload_hash     CHAR(64)    NOT NULL UNIQUE,
    article_id       BIGINT      NOT NULL,
    pipeline_version VARCHAR(50) NOT NULL,
    payload_json     JSONB       NOT NULL,
    status           VARCHAR(20) NOT NULL DEFAULT 'recebido'
                     CHECK (status IN ('recebido','processado','rejeitado','erro')),
    tentativas       INT         NOT NULL DEFAULT 0,
    recebido_em      TIMESTAMPTZ NOT NULL DEFAULT now(),
    processado_em    TIMESTAMPTZ,
    erro             TEXT
);
CREATE INDEX ix_analyser_inbox_artigo  ON analyser_inbox_evento (article_id, pipeline_version);
CREATE INDEX ix_analyser_inbox_pendente ON analyser_inbox_evento (status)
    WHERE status <> 'processado';

CREATE TABLE analyser_item (
    item_id                       TEXT        PRIMARY KEY,
    evento_id                     BIGINT      NOT NULL REFERENCES analyser_inbox_evento (evento_id),
    article_id                    BIGINT      NOT NULL,
    entity_type                   VARCHAR(20) NOT NULL
                                  CHECK (entity_type IN ('politico','partido')),
    nr_titulo_eleitoral_candidato VARCHAR(20),
    nr_partido                    INT,
    ator_nome                     VARCHAR(255) NOT NULL,
    id_midia                      INT,
    link_noticia                  TEXT,
    data_publicacao               TIMESTAMPTZ,
    janela_mes                    CHAR(7)     NOT NULL,
    rotulo_definitivo             VARCHAR(10) NOT NULL
                                  CHECK (rotulo_definitivo IN ('positivo','negativo','neutro')),
    regra_agregacao_versao        VARCHAR(30) NOT NULL,
    trechos_json                  JSONB       NOT NULL,
    conteudo_hash                 CHAR(64)    NOT NULL,
    resumo                        TEXT,
    temas_json                    JSONB,
    modelo                        VARCHAR(100),
    hash_prompt_resumo            CHAR(64),
    resumido_em                   TIMESTAMPTZ,
    status                        VARCHAR(20) NOT NULL DEFAULT 'novo',
    criado_em                     TIMESTAMPTZ NOT NULL DEFAULT now(),
    atualizado_em                 TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT ck_analyser_item_uma_entidade
        CHECK (num_nonnulls(nr_titulo_eleitoral_candidato, nr_partido) = 1)
);
CREATE INDEX ix_analyser_item_janela ON analyser_item
    (janela_mes, entity_type, nr_titulo_eleitoral_candidato, nr_partido);
CREATE INDEX ix_analyser_item_artigo ON analyser_item (article_id);

CREATE TABLE analyser_execucao (
    execucao_id          BIGSERIAL   PRIMARY KEY,
    numero_execucao      INT         NOT NULL,
    status               VARCHAR(20) NOT NULL
                         CHECK (status IN ('em_andamento','concluida','falhou')),
    capacidade_lote      INT         NOT NULL,
    quantidade_eventos   INT         NOT NULL DEFAULT 0,
    quantidade_itens     INT         NOT NULL DEFAULT 0,
    quantidade_resumos   INT         NOT NULL DEFAULT 0,
    quantidade_panoramas INT         NOT NULL DEFAULT 0,
    modelo               VARCHAR(100),
    iniciado_em          TIMESTAMPTZ NOT NULL DEFAULT now(),
    finalizado_em        TIMESTAMPTZ,
    auditoria_json       JSONB,
    erro                 TEXT
);

CREATE TABLE analyser_panorama (
    panorama_id                   BIGSERIAL   PRIMARY KEY,
    execucao_id                   BIGINT      REFERENCES analyser_execucao (execucao_id),
    entity_type                   VARCHAR(20) NOT NULL
                                  CHECK (entity_type IN ('politico','partido')),
    nr_titulo_eleitoral_candidato VARCHAR(20),
    nr_partido                    INT,
    ator_nome                     VARCHAR(255) NOT NULL,
    janela_mes                    CHAR(7)     NOT NULL,
    eixo                          VARCHAR(10) NOT NULL
                                  CHECK (eixo IN ('positivo','negativo','neutro')),
    versao                        INT         NOT NULL CHECK (versao >= 1),
    formato                       VARCHAR(20) NOT NULL,
    total_itens                   INT         NOT NULL,
    texto                         TEXT        NOT NULL,
    temas_json                    JSONB       NOT NULL,
    fontes_json                   JSONB       NOT NULL,
    avisos_json                   JSONB       NOT NULL DEFAULT '[]'::jsonb,
    quantidade_lotes              INT         NOT NULL,
    modelo                        VARCHAR(100),
    hashes_prompts_json           JSONB,
    criado_em                     TIMESTAMPTZ NOT NULL DEFAULT now(),
    publicado_em                  TIMESTAMPTZ,
    CONSTRAINT ck_analyser_panorama_uma_entidade
        CHECK (num_nonnulls(nr_titulo_eleitoral_candidato, nr_partido) = 1)
);

CREATE UNIQUE INDEX uk_analyser_panorama_versao ON analyser_panorama (
    entity_type,
    COALESCE(nr_titulo_eleitoral_candidato, ''),
    COALESCE(nr_partido, -1),
    janela_mes,
    eixo,
    versao
);
Sobre o índice único com valores nulos

No comportamento padrão do PostgreSQL, dois NULL são considerados distintos numa restrição UNIQUE. Como um dos dois campos de ator é sempre nulo, um UNIQUE comum não impediria duplicatas — é uma armadilha que já foi observada em tabela_classificacao.

A DDL acima resolve com COALESCE dentro de um índice de expressão, o que funciona em qualquer versão. Em PostgreSQL 15 ou superior, a alternativa mais direta é declarar UNIQUE NULLS NOT DISTINCT. Qual das duas usar é decisão do responsável pelo banco.

Chaves estrangeiras para tabelas existentes

A DDL proposta não cria chave estrangeira de analyser_item.id_midia para tabela_midia, nem de article_id para qualquer tabela do Classifier. A intenção é manter as tabelas do Analyser não invasivas: uma FK faria uma remoção do lado do Classifier falhar por causa de linhas do Analyser.

Se for preferível ter a integridade referencial garantida pelo banco, a FK para tabela_midia pode ser acrescentada sem prejuízo funcional.
