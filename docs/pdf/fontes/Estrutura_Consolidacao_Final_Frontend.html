Estrutura da Consolidação Final

Contrato de dados do Prisma Analyser para tipagem e exibição no frontend

Os exemplos deste documento são saída real do módulo, gerada com o modelo qwen3.5:9b · Setembro de 2026

1. O modelo mental

A consolidação final produz um panorama por ator, por mês, por eixo. Eixo é o agrupamento de sentimento da cobertura: positivo, negativo ou neutro.

Ou seja, uma tela de "Lula em agosto de 2026" reúne três registros — um de cada eixo — e não um só. Os três têm exatamente a mesma forma; o que muda é o que o texto reúne.

ator 122418060191 + janela "2026-08"
   ├── eixo "negativo"  → 1 panorama (versão mais recente)
   ├── eixo "positivo"  → 1 panorama (versão mais recente)
   └── eixo "neutro"    → 1 panorama (versão mais recente)
Um eixo pode não existir

Se nenhuma notícia daquele ator naquele mês foi classificada como positiva, não há panorama positivo — não é um objeto vazio, é a ausência do registro. A tela precisa de estado vazio por eixo, não só um estado vazio geral.

2. Tipos TypeScript

Pronto para copiar. Corresponde ao que o módulo grava hoje.

export type Eixo = "positivo" | "negativo" | "neutro";
export type ItemId = string;

export interface TemaContado {
  tema: string;          // 1 a 4 palavras
  ocorrencias: number;   // quantas matérias distintas sustentam o tema
  fontes: ItemId[];      // os ids dessas matérias
}

export interface Panorama {
  ator_id: string;       // título eleitoral (político) ou número (partido)
  janela: string;        // "YYYY-MM"
  eixo: Eixo;
  total_itens: number;   // matérias distintas no panorama
  temas: TemaContado[];  // nunca vazio
  fontes: ItemId[];      // nunca vazio
  texto: string;         // o parágrafo consolidado; nunca vazio
}

export interface RegistroPanorama {
  ator_id: string;
  janela: string;
  eixo: Eixo;
  versao: number;        // 1, 2, 3... exibir apenas a maior
  formato: Eixo;         // hoje repete o eixo; ignorar na tela
  panorama: Panorama;    // o conteúdo fica aqui dentro
  avisos: string[];      // divergências técnicas de verificação
  lotes: number;         // métrica operacional, não é contagem de notícias
  modelo: string;        // ex.: "qwen3.5:9b"
  hash_prompt_lote: string;
  hash_prompt_final: string;
  hash_prompt_formato: string;
  rodada: string;
  criado_em: string;     // ISO 8601
}
Atenção ao aninhamento

O conteúdo que vai para a tela está em registro.panorama, não na raiz. Os campos da raiz que também aparecem dentro (ator_id, janela, eixo) são duplicados de propósito, para permitir filtrar sem abrir o objeto aninhado.

Campos do RegistroPanorama que não vão para a tela comum

CampoExpor?Por quê
versaoComo filtroA API deve devolver apenas a maior versão de cada (ator, janela, eixo). Versões antigas existem para auditoria, não para leitura.

No exemplo desta página, lotes: 1 com total_itens: 4 significa que as quatro notícias couberam numa chamada só. Quem conta notícias é total_itens.

modelo, hash_prompt_*, rodadaNãoRastreabilidade técnica. Útil numa tela de auditoria, com autorização própria.
criado_emSimPode alimentar um "atualizado em".

Como os três eixos aparecem na mesma janela

Negativo · 4 matérias · 4 temas

“As críticas registradas pela cobertura do mês concentram-se em questionamentos sobre a gestão econômica e as alianças políticas do governo federal. O noticiário registra cobranças de que o consumo brasileiro estaria caindo devido ao dinheiro indo para jogos de azar…”

Positivo · 4 matérias · 4 temas

“Os elogios registrados pela cobertura do mês concentram-se na postura estratégica de Luiz Inácio Lula da Silva durante a campanha para sua reeleição…”

Neutro · 4 matérias · 3 temas

“O registro factual da cobertura do mês concentra-se em dados eleitorais e movimentações políticas no âmbito do Judiciário. As matérias apresentam resultados de pesquisas que indicam o presidente Lula à frente no primeiro turno…”

5. Regras que a tela precisa respeitar

  1. Exibir só a maior versao de cada (ator, janela, eixo). Panoramas são versionados e nunca sobrescritos; mostrar todos duplicaria o conteúdo na tela.
  2. Não reescrever o texto. Ele já vem pronto, sem ids na prosa, e a primeira frase nomeia o recorte de propósito. Cortar ou resumir quebra essa garantia.
  3. Manter os nomes dos eixos. O módulo mede sentimento da cobertura, não posição ideológica. Rotular como "viés" ou "espectro" afirma algo que o dado não sustenta.
  4. Tratar ocorrencias como contagem de matérias, não de menções ou parágrafos.
  5. Ter estado vazio por eixo, porque um eixo pode simplesmente não existir naquela janela.

6. Identidade do ator e das fontes

O nome do ator vem junto

O ator_id na seção 2 é o formato que o modelo de IA produz: um único campo de texto, o título eleitoral (122418060191), que não deve ser exibido. É a mesma forma usada hoje no arquivo panoramas.json — ainda não existe banco de dados no Analyser, essa parte é proposta.

Na tabela que está sendo proposta para o banco, esse identificador não fica como um campo só: ele se decompõe em duas colunas tipadas (nr_titulo_eleitoral_candidato para político, nr_partido para partido — sempre uma delas nula), o que permite índice e busca direta no banco. O nome legível ganha coluna própria (ator_nome), e é isso que a API devolve ao frontend — sem exigir que a tela resolva identificador nenhum.

O nome guardado é um retrato do momento da geração. Se a carga de entidades for refeita e o nome mudar, o registro antigo preserva o nome com que o texto foi escrito.

As fontes não têm manchete nem link

fontes traz ids como art_1559__politico_122418060191. Para montar uma lista de "notícias que sustentam este panorama" com título, veículo e link, é preciso um endpoint que resolva esses ids.

E há uma limitação real a considerar no desenho: o título da notícia não existe hoje em nenhuma tabela do banco. O que existe é o link e o veículo. Enquanto o Classifier não persistir o título, uma lista de fontes só pode mostrar veículo e link — não a manchete.

DTO sugerido para a API

O módulo grava um registro por eixo. A tela quer os três juntos. A agregação é trabalho da API:

export interface PanoramaDaJanela {
  ator: { id: string; tipo: "politico" | "partido"; nome: string };
  janela: string;
  atualizado_em: string;
  eixos: Partial<Record<Eixo, {
    total_itens: number;
    texto: string;
    temas: TemaContado[];
  }>>;                        // Partial: um eixo pode não existir
  fontes: Array<{
    item_id: ItemId;
    veiculo: string | null;
    url: string | null;
    data: string | null;
    titulo: string | null;     // hoje sempre null
    rotulo: Eixo;
  }>;
}

7. Campos que foram removidos — não tipar

Versões anteriores do contrato traziam dois campos que não existem mais. Se aparecerem em algum documento ou amostra antiga, estão desatualizados:

Campo removidoO que aconteceu
fatos_mais_citadosEra uma lista de fatos soltos, cada um com sua descrição e fontes. Os mesmos fatos agora chegam consolidados dentro de texto, em um parágrafo único.
respostas_registradasRegistrava se a cobertura trazia manifestação de quem foi citado. Foi retirado por decisão de produto: media as manifestações de qualquer citado, não o contraditório do alvo, e o insumo disponível não sustentava a leitura.
Sobre o que o panorama descreve

Todo texto produzido descreve o que a cobertura registra, nunca um juízo sobre o ator. É por isso que os parágrafos abrem com "as matérias apontam", "o noticiário registra". A interface deve preservar esse enquadramento: o produto lê o noticiário, não julga quem ele cita.
